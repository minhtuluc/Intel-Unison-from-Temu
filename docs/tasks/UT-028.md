# UT-028 — Seam transport ở frontend + module framing/backpressure/transport

Status: ready-for-agent (M5 — **chờ gate UT-026**)
Depends on: UT-025, UT-026 (gate)
Owner / file ownership: `public/js/transfer.js`, `public/js/p2p/framing.js` (mới), `public/js/p2p/backpressure.js` (mới), `public/js/p2p/transport.js` (mới), `public/js/capabilities.js`, `public/sw.js`

Problem and evidence: `TransferEngine._startUpload` (`public/js/transfer.js`) là seam duy nhất để chọn transport, nhưng nó gắn cứng vào XHR/HTTP; chưa có framing, backpressure hay kiểm tra toàn vẹn cho DataChannel. Ngoài ra `public/sw.js` có danh sách `STATIC_ASSETS` viết tay và **đang thiếu `relay-inbox.js`** — module mới nếu không thêm tay sẽ không được precache.

In scope: dispatch theo transport trong `_startUpload` (mặc định vẫn là đường relay/HTTP → hành vi không đổi); `framing.js` (encode/decode + validate frame có `fileIndex`, từ chối frame quá `p2pMaxFrameBytes` hoặc index ngoài tập đã accept); `backpressure.js` (scheduler theo `bufferedAmount` + `bufferedamountlow`); **receiver sink** (xem dưới); `transport.js` (wrapper `RTCPeerConnection`/`RTCDataChannel`, state machine `connecting → connected → completed | failed` + timeout, trả `failed` để quyết định fallback); `supportsP2P()` trong `capabilities.js`; thêm module mới + `relay-inbox.js` vào `STATIC_ASSETS` và bump cache version.

Out of scope: bật P2P làm transport mặc định trong UI (thuộc lượt sau khi signaling đã có); signaling server (UT-027); TLS.

**Receiver sink policy (M5-QC-03) — phải chốt trước khi viết transport:**

- Trên HTTP LAN không có File System Access, nên sink là bộ nhớ; vì vậy phải có **trần công khai** `p2pMaxInMemoryBytes` (mặc định 64 MiB).
- File vượt trần → **không thử P2P**, đi relay ngay từ đầu (không truyền byte P2P nào rồi mới thất bại).
- Hash cập nhật **theo từng chunk khi nhận**, không ghép xong mới băm.
- Chỉ finalize (trao file cho người dùng) sau khi checksum khớp; cancel/mismatch phải đóng sink, giải phóng buffer, không để lại file dở.
- Nếu sau này có secure context, sink ghi thẳng ra đĩa sẽ thay sink bộ nhớ và nâng trần — khi đó sửa ADR-0005.

Acceptance criteria: toàn bộ test hiện có của `transfer.js` giữ nguyên xanh sau khi tách seam (chứng minh hành vi không đổi); framing round-trip + từ chối frame sai/thiếu/quá cỡ/sai `fileIndex`; backpressure dừng và tiếp đúng ngưỡng, tiến độ tính theo byte đã gửi thật; transport wrapper báo `failed` đúng hạn khi ICE timeout và phân biệt đúng `connected` vs `completed`; file vượt trần **không** sinh phiên P2P; checksum sai → không trao file và dọn sink; `supportsP2P()` trả false và có câu chữ giải thích khi thiếu API.

Regression scenario: `tests/unit/p2p-framing.test.js`, `tests/unit/p2p-backpressure.test.js`, `tests/unit/p2p-sink.test.js` (**đo peak buffer theo frame/window**, không chỉ test backpressure phía sender), `tests/unit/p2p-transport.test.js` (stub `RTCPeerConnection`, theo mẫu `MockXHR` ở `tests/integration/m1-review-regression.test.js`), `tests/unit/capabilities.test.js`, `tests/unit/pwa.test.js` (asset list).

Verification commands and actual results: chưa thi công.

Remaining risks and handoff: wrapper `RTCPeerConnection` chỉ được kiểm bằng stub trong Node — không thay thế được kiểm chứng browser thật; phải ghi rõ điều đó khi bàn giao.
